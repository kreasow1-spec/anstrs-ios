## 7. Booking Flow

- **Жизненный цикл записи:**
  1. Клиент выбирает дату, временной слот, формат/эскиз и передаёт пожелания.
  2. Запрос отправляется на бэкенд через `/api/v1/...`.
  3. Бэкенд рассчитывает стоимость, размер депозита и резервирует слот.
  4. Бэкенд инициирует платежную сессию депозита в YooKassa.
  5. После серверного подтверждения оплаты статус бронирования переходит в подтверждённый в production JSON DB.
  6. Срабатывает триггер оповещения в Telegram.
- **Ограничения безопасности:**
  - Клиент НЕ может подтвердить бронь без оплаты депозита.
  - Клиент НЕ может самостоятельно менять статус бронирования.

---

## 8. Payment Flow

- **Платёжный шлюз:** ЮKassa (YooKassa).
- **Логика работы:**
  - Инициализация транзакции происходит строго через бэкенд.
  - Мобильный клиент получает платежную сессию (URL / SDK payload).
  - Оплата совершается клиентом.
  - Подтверждение оплаты (`payment.succeeded`) поступает на бэкенд через Webhook ЮKassa.
- **Ограничение безопасности:** Мобильное приложение никогда не передаёт и не устанавливает флаг `paid=true`. Успех оплаты определяет только сервер.

## 16. Целевая iOS Architecture

- **Платформа:** React Native + Expo + TypeScript.
- **Маршрутизация:** Expo Router.
- **Управление состоянием:**
  - **Server State:** TanStack Query (`@tanstack/react-query`) — единственный инструмент для серверных данных, кэширования, инвалидации и синхронизации.
  - **Local / UI State:** Zustand — для легковесного локального клиентского состояния (модальные окна, фильтры, активный шаг формы).
- **Хранилища:**
  - `Expo SecureStore` — для токенов авторизации и чувствительных ключей.
  - `MMKV` / `AsyncStorage` — для быстрого локального кэша и настроек UI.
- **Компоненты ядра:**
  - `react-native-reanimated` (анимации 60/120 fps).
  - `react-native-gesture-handler` (нативные свайпы и жесты).
  - `expo-image` (кэширование, blurhash, плавный рендеринг).
  - `expo-image-picker` (выбор референсов и съёмка фото).
  - `expo-haptics` (тактильная отдача).

## 19. Security Requirements (Критически важно)

1. **Untrusted Client Model:** Клиент работает в недоверенной среде.
2. **Запрет клиентского авторитета:** Приложению запрещено доверять переданным с клиента:
   - `userId`;
   - Роли (`admin` / `client`);
   - Стоимости сеанса (`price`);
   - Сумме депозита (`deposit`);
   - Статусам оплаты (`paid = true`);
   - Правам на владение чужой записью (`booking ownership`).
3. **Все транзакции и смены статусов** подтверждаются исключительно бэкендом через серверную верификацию и вебхуки.
